# Backlog de Historias de Usuario (HU-001 a HU-048)

## Épica EP01 – Configuración inicial mínima

### HU-001: Ingreso rápido a la aplicación
- **Descripción:** Como estudiante con poco tiempo, quiero ingresar a la aplicación sin completar un registro extenso, para empezar a usarla en pocos segundos.
- **Criterios de Aceptación:**
  - **CA01:** La pantalla de ingreso debe ofrecer la opción "Continuar como invitado" de forma visible.
  - **CA02:** El ingreso con correo debe solicitar únicamente correo y contraseña.
  - **CA03:** El sistema debe permitir llegar a la pantalla de inicio en no más de dos interacciones desde la apertura.
- **Escenarios (Gherkin):**
  1. **Ingreso como invitado**
     - **DADO** que el estudiante abre la aplicación por primera vez
     - **CUANDO** selecciona el botón "Continuar como invitado"
     - **ENTONCES** el sistema lo lleva a la configuración inicial sin solicitar datos personales.
  2. **Contraseña vacía**
     - **DADO** que el estudiante eligió ingresar con su correo y dejó vacío el campo "Contraseña"
     - **CUANDO** selecciona el botón "Ingresar"
     - **ENTONCES** el sistema no avanza y muestra que la contraseña es obligatoria.

### HU-002: Configuración mínima inicial
- **Descripción:** Como estudiante con poco tiempo, quiero indicar mi tiempo habitual de pausa, mi presupuesto diario y mi lugar habitual, para recibir recomendaciones ajustadas sin llenar formularios extensos.
- **Criterios de Aceptación:**

  - **CA02:** Cada dato debe poder elegirse con opciones predefinidas, sin necesidad de escribir.
  - **CA03:** El sistema debe mostrar el progreso del paso (por ejemplo, "1 de 3").
  - **CA04:** Al finalizar, el sistema debe guardar los datos y mostrar la pantalla de inicio.
- **Escenarios (Gherkin):**
  1. **Configuración completa**
     - **DADO** que el estudiante se encuentra en la configuración inicial
     - **CUANDO** selecciona su tiempo, presupuesto y lugar, y pulsa "Continuar"
     - **ENTONCES** el sistema guarda sus preferencias y muestra la pantalla de inicio.
  2. **Dato pendiente**
     - **DADO** que el estudiante no ha seleccionado su presupuesto
     - **CUANDO** pulsa el botón "Continuar"
     - **ENTONCES** el sistema indica el dato pendiente y conserva los valores ya elegidos.

### HU-048: Compartir una alternativa alimentaria
- **Descripción:** Como estudiante que coordina su comida con compañeros, quiero compartir una alternativa mediante un enlace o resumen, para facilitar la elección conjunta.
- **Criterios de Aceptación:**
  - **CA01:** El detalle debe mostrar una acción «Compartir».
  - **CA02:** El contenido compartido debe incluir nombre, precio referencial y lugar sin datos personales.
  - **CA03:** Si el navegador no admite compartir, debe ofrecerse «Copiar información».
- **Escenarios (Gherkin):**
  1. **Compartir opción**
     - **DADO** que el estudiante visualiza el detalle de una alternativa
     - **CUANDO** pulsa «Compartir»
     - **ENTONCES** el sistema prepara un resumen con nombre, precio y lugar.
  2. **Copiar información**
     - **DADO** que la función de compartir no está disponible
     - **CUANDO** selecciona «Copiar información»
     - **ENTONCES** el sistema permite copiar el resumen de la alternativa.
